# ADR 002: Why Strategy Plugin/Registry?

- **Status**: Accepted
- **Date**: 2026-08-19
- **Author**: Người 2 (Vũ Thành Đạt)

## Context
The system needs to support evaluating many trading strategies. New strategies might be added frequently by different developers or automatically generated by the search algorithm. We need a way to add these strategies without modifying the core system logic, preventing merge conflicts and tight coupling.

## Decision
We decided to use the Strategy Pattern coupled with a central Registry.
1. Every strategy must implement a common `Strategy` interface (Go: `type Strategy interface { Name() string; Analyze(candles []market.Candle) Signal }`).
2. A `StrategyRegistry` holds a map of registered strategies in memory.
3. Adding a new strategy involves creating a new struct implementing the interface, and adding one `Register()` call during application startup.

## Alternatives Considered
- **Hard-coded switch/if-else logic**: Easiest to start, but violates Open-Closed Principle. Every new strategy requires modifying the evaluator core.
- **Config files / DSL scripting**: Strategies written in a domain-specific language (e.g., Lua or JSON config). This adds significant complexity (a DSL parser/engine) which is overkill for a 2-week lab project where all developers know Go.
- **Go Plugins (buildmode=plugin)**: Allows hot-swapping strategies without recompiling the main binary. However, Go plugins are notoriously brittle, OS-dependent, and hard to debug.

## Consequences
- **Pros**: 
  - High extensibility (satisfies Architecture Proof).
  - High testability: each strategy can be unit-tested in isolation by just providing a slice of mock candles.
- **Cons**: 
  - Strategies must be compiled into the binary.
  - Adding a new strategy still requires a redeployment (acceptable for this scope).

## Evidence
- We created an `extension_test.go` that defines a `DummyStrategy` and registers it without modifying the registry code.
- The `GET /strategies` endpoint correctly returns the dynamic list of registered strategies without any hardcoding.
